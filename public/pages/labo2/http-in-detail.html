HTTP in Detail

Contexte

Cette room explique HTTP de façon concrète : structure d’une requête et d’une réponse, méthodes, en-têtes, cookies, codes de statut, et pourquoi HTTPS change la donne sur la confidentialité et l’intégrité.

Points clés

Le point clé dans ce contexte, c’est que le web n’est pas “une page”, c’est une suite d’échanges. Chaque clic peut déclencher plusieurs requêtes, avec des en-têtes qui portent du contexte.

Les méthodes (GET/POST surtout) et l’idée que certaines actions doivent être confirmées côté serveur, pas seulement côté interface, sont mieux comprises dans cette logique. Les codes HTTP ne sont pas anecdotiques : ils disent si la ressource existe, si on est redirigé, si l’accès est refusé, ou si le serveur est en erreur.

Les cookies et mécanismes de session expliquent aussi pourquoi une petite faille peut devenir grosse : si on peut voler ou rejouer une session, on ne “pirate” pas toujours le mot de passe directement.
