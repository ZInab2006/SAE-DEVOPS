VPN TryHackMe (OpenVPN) et connexions distantes

🧭 Contexte

Plusieurs rooms TryHackMe proposent des machines sur un réseau privé : sans VPN, votre poste ne peut pas joindre ces cibles comme le ferait un attaquant ou un analyste dans un labo. Cette page comporte deux volets : d’abord OpenVPN (captures d’écran, Linux), puis RDP (Remote Desktop) pour ouvrir le bureau distant d’une machine Windows du lab lorsque la room l’exige.

💭 Pourquoi utiliser le VPN TryHackMe ?

Le VPN crée un tunnel chiffré entre votre machine et le réseau TryHackMe. Concrètement, cela permet :

  • d’accéder aux machines de la room (adresses internes, scans, exploitation) comme si vous étiez sur le même réseau que le lab ;
  • de séparer ce trafic du reste de votre navigation tout en restant dans un cadre pédagogique ;
  • de valider la connectivité avant de lancer des outils (ping, nmap, navigateur vers une IP de room, etc.).

Sans cette étape, beaucoup d’exercices « ne répondent pas » alors que la cause est simplement l’absence de tunnel VPN actif.

Étape 1 — Accéder à la page d’accès VPN

Rendez-vous sur la page officielle d’accès TryHackMe pour récupérer le client et les consignes : https://tryhackme.com/access. Vous y choisissez notamment la configuration OpenVPN adaptée à votre système (ici nous détaillons Linux).

Étape 2 — Télécharger le fichier .ovpn

TryHackMe fournit un fichier de configuration personnel (souvent nommé avec votre identifiant ou « user », extension .ovpn). Téléchargez-le : il contient les paramètres nécessaires pour joindre le réseau du lab. Sur la capture ci-dessous, le fichier est enregistré sur le PC (par défaut souvent le dossier Téléchargements).

Étape 3 — Lancer OpenVPN en ligne de commande (Linux)

Vérifiez d’abord qu’OpenVPN est installé sur votre distribution (paquet openvpn ou équivalent). Placez-vous dans le dossier où se trouve le fichier, ou indiquez le chemin complet. Le fichier est en général dans ~/Téléchargements ou ~/Downloads selon la langue du système.

Exemple de commande (adapter le nom du fichier et le chemin) : 

sudo openvpn /chemin/vers/votre-fichier.ovpn

Laisser le terminal ouvert : la session VPN reste active tant que le processus tourne. Utiliser Ctrl+C pour arrêter la connexion.

Étape 4 — Vérifier la connexion (ping)

Une fois le tunnel établi, un test simple consiste à envoyer un ping vers une adresse fournie dans la room (ou vers la cible indiquée dans l’énoncé). Des réponses reçues confirment que vous êtes bien connecté au réseau TryHackMe.

💻 Windows, macOS ou autre environnement

Si vous n’êtes pas sous Linux, TryHackMe propose un guide pas à pas pour d’autres systèmes (install du client, import du .ovpn, etc.) sur la room dédiée : https://tryhackme.com/room/openvpn.

🖥️ La connexion RDP (bureau distant)

Le RDP permet de contrôler l’interface graphique d’une machine Windows distante. Sur TryHackMe, certaines rooms fournissent une cible Windows accessible en RDP une fois le VPN actif.

💭 À quoi sert le RDP ici ?

  • Utiliser des outils graphiques sur la machine du lab (Active Directory, navigateur sur la cible, bureaux Windows « réels ») ;
  • Suivre des scénarios qui imitent un poste utilisateur ou un serveur, là où SSH seul ne suffit pas ;
  • Travailler comme en entreprise avec un client bureau à distance, tout en restant dans l’environnement d’apprentissage.

Les identifiants (utilisateur, mot de passe) et l’adresse ou le port RDP sont indiqués dans la room ou sur la fiche machine TryHackMe : il faut les reprendre tels quels pour la connexion.

📋 Prérequis avant d’ouvrir une session RDP (TryHackMe)

  1. VPN OpenVPN connecté (voir la partie 1 ci-dessus) — sans VPN, l’IP interne du lab n’est pas joignable.
  2. Noter l’IP (ou le hostname) de la machine, le port si ce n’est pas le port par défaut 3389, ainsi que utilisateur / mot de passe (fournis par la room).
  3. Linux : client xfreerdp ou Remmina — voir la section suivante. Pour Windows ou macOS, utiliser le client adapté en reprenant les mêmes paramètres (adresse, port, comptes) une fois les notions générales comprises via le lien IT-Connect ci-dessus.

🛠️ RDP sous Linux (xfreerdp)

Sur de nombreuses distributions, le paquet s’appelle freerdp ou freerdp2 (binaire souvent xfreerdp). Exemple de commande (à adapter avec l’IP, le port, le login et le mot de passe fournis par la room) : 

xfreerdp /v:ADRESSE_IP:3389 /u:NOM_UTILISATEUR /p:'MOT_DE_PASSE' /dynamic-resolution +clipboard

Les certificats des machines de lab sont souvent auto-signés : le client peut afficher un avertissement. En environnement TryHackMe uniquement, on peut accepter une option du type /cert:ignore ou répondre « oui » à la question du terminal selon la version de FreeRDP (voir xfreerdp --help).

Alternative graphique : Remmina (protocole RDP, même paramètres : serveur, port, identifiants).

✅ Vérifier que la session fonctionne

Après connexion, le bureau Windows du lab doit s’afficher. Si la fenêtre reste noire ou se ferme tout de suite, vérifier le VPN, le port, et que la machine est bien démarrée dans l’interface TryHackMe (bouton Start Machine / équivalent).

Pour aller plus loin sur l’accès réseau côté TryHackMe, la page https://tryhackme.com/access reste le point d’entrée officiel (VPN, puis utilisation des machines de la room).

🔒 Sécurité et bonnes habitudes

  • Utiliser RDP uniquement vers les cibles du lab TryHackMe, pas vers des systèmes réels sans autorisation.
  • Ne pas réutiliser en production les mots de passe « de démo » donnés dans les rooms.
  • Fermer la session RDP et le VPN lorsque vous avez terminé, surtout sur un poste partagé.
