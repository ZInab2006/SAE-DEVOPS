Structure du site

Contexte

Le site est volontairement organisé comme une application à page unique (SPA légère) : une seule index.html sert de coquille, et le contenu des « pages » est injecté dans une zone dédiée sans recharger toute la page. Ce choix simplifie la navigation, évite de dupliquer menu et pied de page sur chaque fichier HTML, et reste entièrement compatible avec Firebase Hosting (fichiers statiques + règle de rewrite vers index.html).

La structure vise trois objectifs pour la SAE : cohérence visuelle (mêmes styles partout), sécurité minimale (on ne charge que des fragments autorisés), et maintenabilité (un membre ajoute un fichier sous public/pages/, l’inscrit dans la liste du routeur, et le menu peut pointer vers ?page=...).

Organisation des fichiers

  • Point d’entrée unique : public/index.html charge les polices, Bootstrap, css/styles.css et les scripts dans l’ordre (include.js puis router.js, etc.). Le corps contient uniquement #menu, #content et #footer.
  • Partials : public/partials/menu.html et footer.html sont récupérés par fetch puis injectés dans le DOM au chargement (voir include.js).
  • Routeur : l’URL ?page=nom (ex. ?page=labo1/search-skills) détermine quel fragment HTML est chargé depuis public/pages/. Une whitelist allowedPages dans router.js empêche de demander un chemin arbitraire (ex. lecture de fichiers sensibles).
  • Pages : regroupées par labo — labo1/, labo2/, labo3/ — plus des dossiers special/, members/, et les pages racine logiques (home, team, rooms, etc.).
  • Assets : images sous public/img/ (équipe, icônes), feuille de style unique public/css/styles.css, scripts sous public/js/ (thème, animations, navigation des rooms, etc.).

2. Partials — public/js/include.js (menu + footer)

function loadHTML(id, file) {
  fetch(file)
    .then(response => {
      if (!response.ok) throw new Error(`Erreur chargement ${file}`);
      return response.text();
    })
    .then(data => {
      document.getElementById(id).innerHTML = data;
    })
    .catch(error => console.error(error));
}

document.addEventListener("DOMContentLoaded", () => {
  loadHTML("menu", "partials/menu.html");
  loadHTML("footer", "partials/footer.html");
});

3. Routeur — public/js/router.js (whitelist + chargement)

const allowedPages = [
  "home",
  "team",
  "special/site-structure",
  "labo1/search-skills",
  // ... autres pages autorisées
];

function loadPage(page) {
  if (!allowedPages.includes(page)) page = "home";
  fetch(`pages/${page}.html`)
    .then(r => { if (!r.ok) throw new Error("Page non trouvée"); return r.text(); })
    .then(data => { document.getElementById("content").innerHTML = data; })
    .catch(() => {
      document.getElementById("content").innerHTML =
        "<h1>404 - Page non trouvée</h1>";
    });
}

function getPageFromURL() {
  const params = new URLSearchParams(window.location.search);
  return params.get("page") || "home";
}

document.addEventListener("DOMContentLoaded", () => {
  loadPage(getPageFromURL());
});

4. Styles globaux — public/css/styles.css (variables + thème)

Le fichier commence par le bloc :root : couleurs, ombres, polices (dont --font-display pour les titres). Le sélecteur [data-theme="light"] redéfinit les mêmes variables pour le thème clair. L’ensemble assure un rendu cohérent sur toutes les pages (cartes, liens, blocs de code, menu) ; le bouton de thème du menu pilote ces variables via theme.js (dataset.theme sur l’élément racine).
