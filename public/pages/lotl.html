Living Off The Land

Contexte

Le sujet Living Off The Land décrit des attaques qui réutilisent des outils natifs du système au lieu d’introduire un malware classique. L’attaquant cherche à rester discret en utilisant des commandes légitimes déjà présentes sur la machine.

Cette page se limite à expliquer le concept, les familles de techniques et les ressources utiles ; il n’y a pas de démonstration ni d’exercice de labo ici.

Points clés

Cette approche complique la détection car l’activité peut ressembler à de l’administration normale. Des outils comme PowerShell, WMI ou cmd peuvent être détournés pour l’exécution, le mouvement latéral et la collecte d’informations.

La défense doit donc se concentrer sur le comportement : surveillance des commandes sensibles, restriction des privilèges, journalisation centralisée, et règles de détection basées sur les séquences d’actions.

En bref

Living Off The Land montre que la confiance dans les outils système ne suffit pas. Une bonne protection passe par l’observabilité, la limitation des droits et l’analyse contextuelle des actions exécutées.

Origine et idée générale

L’expression Living Off the Land vient de l’idée de « vivre de ce que la terre offre » : comme en vrai, l’adversaire exploite ce qui est déjà sur la machine (outils et utilitaires intégrés) plutôt que d’empiler des binaires suspects. Le terme a été popularisé à DerbyCon en 2013 et reste central en red team.

L’objectif principal est d’utiliser des programmes, scripts ou bibliothèques signés Microsoft pour se fondre dans l’activité légitime et limiter la détection. Exemple classique : détourner CertUtil pour télécharger un fichier sans rapport avec la gestion des certificats.

Les grands volets couverts par ce type d’approche incluent notamment :

  • reconnaissance ;
  • opérations sur les fichiers ;
  • exécution de code arbitraire ;
  • mouvement latéral ;
  • contournement des produits de sécurité.

Windows Sysinternals

Sysinternals regroupe des utilitaires avancés pour administrer, diagnostiquer et dépanner Windows (disques, processus, réseau, informations système, sécurité). L’usage en ligne de commande impose souvent d’accepter la licence Microsoft, par exemple avec l’argument -accepteula, ou via une case à cocher au premier lancement.

La suite ne nécessite pas d’installation classique : on peut récupérer les outils via le site Microsoft, le partage réseau Sysinternals Live (\\live.sysinternals.com\tools) ou en ligne de commande. Exemples d’outils souvent cités : AccessChk, PsExec, ADExplorer, ProcDump, ProcMon, TCPView, les PsTools, Portmon, Whois.

Même s’ils sont légitimes pour les admins, ces binaires profitent de la confiance du système : les attaquants et les équipes rouges peuvent donc les abuser pour rester discrets, ce qui pousse les éditeurs de sécurité à surveiller aussi ces usages.

LOLBAS (Living Off the Land Binaries And Scripts)

LOLBAS est un projet communautaire qui recense et documente des binaires, scripts et bibliothèques signés Microsoft utilisables comme techniques LOTL. On peut y chercher par nom de fichier, par fonction, ou en croisant avec MITRE ATT&CK.

Sur le site du projet, la barre de recherche accepte des préfixes utiles : par exemple /execute pour filtrer sur une fonction, ou #Binary, #Script, #Libraries, #OtherMSBinaries pour filtrer par type.

Pour qu’un outil soit retenu, il doit en général :

  • être un fichier signé Microsoft, natif au système ou téléchargé depuis Microsoft ;
  • offrir des usages « intéressants » au-delà du scénario d’usage prévu ;
  • pouvoir servir un scénario type APT ou red team.

Les familles de fonctionnalités documentées incluent entre autres l’exécution de code, les opérations fichiers (téléchargement, copie…), la compilation, la persistance, le contournement UAC, le dump mémoire et l’injection.

Équivalent côté Linux / Unix : le projet GTFOBins, sur le même principe pour les binaires Unix.

Exemples — opérations sur les fichiers

Certutil sert normalement aux certificats, mais on peut l’utiliser pour télécharger des fichiers depuis une URL ou pour encoder/décoder du contenu (techniques souvent référencées côté ATT&CK comme transfert d’outil ou obfuscation de fichiers).

BITSAdmin pilote le service BITS (transferts HTTP/SMB en arrière-plan) : un attaquant peut créer un job pour récupérer ou envoyer un fichier de façon discrète.

FindStr sert à chercher des chaînes dans des fichiers ; un usage détourné consiste à lire un fichier distant via un partage SMB et à rediriger la sortie vers un fichier local, ce qui ressemble à un copier-coller « par la ligne de commande ».

La liste complète des variantes est maintenue dans le projet LOLBAS.

Exemples — exécution et contournement

Exécution détournée : l’Explorateur Windows (explorer.exe) peut lancer d’autres programmes ; WMIC peut créer des processus via WMI ; rundll32 charge des DLL et peut exécuter du code via des chemins comme JavaScript embarqué — le tout en s’appuyant sur des binaires signés et souvent whitelistés.

Contournement de whitelisting applicatif : regsvr32 enregistre des DLL mais peut aussi servir à exécuter du code signé ou distant ; sur certaines configurations, bash.exe (WSL) permet d’exécuter des commandes non prévues par la politique Windows classique.

D’autres idées : raccourcis modifiés pour lancer rundll32, regsvr32 ou un exécutable au clic (ATT&CK — modification de raccourcis) ; outils comme PowerLessShell qui s’appuient sur MSBuild pour exécuter du code sans processus PowerShell visible.

Cas réel : Astaroth (aperçu)

Astaroth est un exemple de malware « fileless » analysé notamment par Microsoft : vol d’informations, évasion (anti-debug, anti-VM…), process hollowing, flux alternatifs NTFS, et recours massif au LOTL. Chaîne d’attaque typique : pièce jointe avec raccourci → commande WMIC pour du JavaScript → BITS pour télécharger plusieurs composants → parfois chaînes cachées (ex. descriptions YouTube) → certutil pour décoder → exécution via regsvr32. Ce cas illustre comment plusieurs briques LOTL s’enchaînent dans un seul incident.
